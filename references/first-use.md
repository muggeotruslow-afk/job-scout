# 首次使用与资料复用

这是 Skill 的对话式引导。下载文件不会自动弹出窗口；在 AI 客户端中首次调用 Job Scout 时执行。用户直接提出找岗请求也必须触发，无需另记初始化命令。

## 先保留原来的任务

记住用户要求的公司、方向、招聘类型和限制，作为 pending_request。不要把“帮我找腾讯AI产品日常实习”变成填完问卷就结束的任务。

执行：

```text
python <skill-dir>/scripts/onboarding.py status
python <skill-dir>/scripts/onboarding.py doctor
```

默认私人目录是 `<skill-dir>/local/user`，已被 Git 忽略。可用 `JOB_SCOUT_DATA_DIR` 或全局参数 `--data-dir <path>` 指定其他本地目录。不要把个人资料存进 examples、references 或 README。

只读取该用户明确提供的资料、已确认的 profile，或明确指定的 Career Ops。检测浏览器依赖不授权读取那个目录的简历。未确认的示例资料不能默认充当用户事实；但有效 profile 中的 confirmed_at 已记录用户此前选择该候选人，包括虚构或模板候选人。新窗口直接复用，不因资料含“虚构”“示例”而要求真实简历、再次选择资料或另说“我在演示”。“适合我的岗位”默认按当前已确认候选人匹配，除非用户明确更换资料。结果保留资料的虚构属性说明即可，不能以此阻止抓取、评分和核验。发现 profile 损坏或未知版本时保留原件，报告原因并重新导入，不覆盖猜测。

## 环境引导

doctor 仅检查依赖是否安装；它不验证网络、浏览器启动或公司接口。不要把 doctor 通过说成整套流程通过。

- Python缺失：引导用户安装Python 3.10+，按客户端权限执行安装或由用户完成。不要让用户粘贴密钥。
- 浏览器依赖缺失：使用项目内的 `npm ci`，需要时再运行 `npx playwright install chromium`。优先复用现有浏览器；明确配置的Career Ops也可提供依赖。
- 其他公司用intern-scout时按README安装可选Python依赖。不要仅因为百度找岗就安装所有备用工具。
- 缺依赖时解释用途；普通安装可按本次任务和客户端权限执行，不重复请求已授权步骤。权限拒绝、验证码、登录或平台条款交给用户，保留未完成状态。
- HTTP接口可以先抓岗位；无法浏览器核验时标记unverified，不能称可投。临时联网故障按README的单进程代理参数处理，不修改系统代理。

## 读取简历并只补问缺失信息

第一句可用：

> 我先读取你的简历，再补齐筛选需要的求职条件。你可以提供文件路径、附件或直接粘贴经历。

如果消息中已有简历，立即读取，不再索要。Markdown、UTF-8文本、DOCX可用 `import-resume --resume <path>` 提取；PDF和图片使用客户端的文档/OCR能力。文本提取不是版式核验，不能宣称已检查简历排版。无法读取时说明具体限制，允许用户粘贴文本，不推断缺失内容。

提取学历、专业、在读状态、毕业时间、经历、职责、技能、指标和作品链接。用户的新材料优先，不从旧画像补入相互冲突的事实。电话、邮箱、性别、照片等不是岗位匹配的必填信息。

优先从原请求和简历填入，只有缺失时再问：

1. 目标岗位与招聘类型（日常实习、暑期/留用或校招）。
2. 接受城市、每周出勤天数、最早到岗时间、连续实习时长。
3. 学历/在读/毕业时间若不清楚，解释会影响资格判断并补问。

第一次补问尽量用一条简短消息把相关条件放在一起，例如：“目标是AI产品日常实习，已从请求读到；还需要你接受的城市、每周出勤、到岗时间和可实习时长。”不要一次抛出十几项泛问题。作品链接、投递历史是可选项，可跳过。不会因为没投递历史而阻止找岗。

用户说不确定或跳过时，保存null，并在岗位资格里标Risk/未知；不要反复追问同一项，更不能默认全国可去、5天或6个月。

## 展示摘要并确认保存

给用户看：目标/招聘类型、学历届别、城市、出勤、到岗、时长，以及几条主要经历和未明确的能力。说明保存的本地目录，不保存联系方式。

> 我会按以上资料筛选，并保存在本地供下次复用。哪些信息需要纠正？如果准确，回复“确认”即可继续本次找岗。

确认是核对提取正确性和保存意愿，不是要求用户担保成果；不能把保存确认当成投递或上传授权。用户已明确授权保存且给出完整条件时，不再要求重复确认，只展示摘要并继续。

先在对话中展示摘要。用户确认保存后，将AI整理的JSON写入私人目录并调用 `save-profile --input <draft> --confirmed`；字段参照 `examples/profile.example.json`。evidence_text保留用户材料的文字证据，resume_source记录来源，pending_request记录原任务。用户明确允许保留未确认草稿时，才使用不带 `--confirmed` 的保存命令；它会保持needs_confirmation。不要未经确认把草稿伪装成ready。

用户不愿保存时，仅在当前会话使用已提供的资料，仍继续找岗；不创建个人profile，不把拒绝持久化当作资格缺失。下次新会话确实没有资料时再引导导入。

```text
python <skill-dir>/scripts/onboarding.py save-profile --input <private-draft-json> --confirmed
```

## 继续原任务与后续复用

保存后立即继续原公司的抓取、筛选、核验和报告，完成后才能结束。若暂缺公司/方向，则只补问该必要项，不重新开始全部引导。

后续status为ready时加载profile，合并用户最新指令并直接执行。ready_with_unknowns说明用户已接受部分条件未知；按Risk处理，不重复强制问卷。若用户换简历或改变条件，仅更新受影响内容，保留其他明确偏好，再按保存授权核对变更。不要每次读取所有历史文件或把别人的profile混入当前候选人。

报告简历来源、仍未知的资格条件、未提供历史时的排除限制，以及公司的实际覆盖范围。评分仍由AI按scoring.md完成，不声称onboarding.py会独立理解所有格式或计算分数。
